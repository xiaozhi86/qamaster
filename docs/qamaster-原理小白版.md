# qamaster 原理小白版：一张图看懂「为什么流程不依赖大模型」

> 这篇文章不写代码，不用行号，用大白话 + 一个贯穿全文的比喻，把 qamaster 的核心原理讲清楚。
> 看完你会明白两件事：**① 它凭什么让流程不受大模型影响；② 你想抄作业该怎么落地。**

---

## 0. 一句话

> **qamaster 把「怎么干活」从「谁来干活」里拆了出来。**
> 大模型只负责"动脑子干活"，而"先干哪步、干完算不算数、干砸了怎么办"这些事，全部交给一套**冷冰冰的、写死的、不靠模型**的程序来管。

---

## 1. 一个比喻：工厂流水线 + 机器质检

想象一条生产流水线，有一个**手艺很好的老师傅**（= 大模型）在干活，还有一个**只认死理的质检系统**（= Runtime）在管流程。

这个老师傅脑子好使，活儿也漂亮，但他有个毛病：**你要是没人盯着，他就会跳步骤、自作主张、甚至干完了糊弄你说"都弄好了"**。

所以 qamaster 干的就一件事：**给老师傅套上一套工单 + 质检的流程，让他只能按部就班地干，而且每一步干没干好、合不合格，由机器说了算，不由他自己说。**

### 三个角色

| 比喻 | qamaster 里的东西 | 干什么 |
|---|---|---|
| 老师傅 | 大模型（LLM Worker） | 动脑子干活、写内容 |
| 质检系统 | Runtime（`runtime/` 目录的程序） | 管流程走到哪了、活合不合格 |
| 工单模板 | Skill（`skills/*/SKILL.md`） | 写清楚"每道工序该干嘛、不该干嘛" |

关键：**老师傅再聪明，也只能在质检系统发给他的工单范围内干活。** 工单之外的事，他想干也干不了——因为那些"按键"根本不在他手里。

---

## 2. 派工单：模型只能看到一张卡

每一步开工前，质检系统会发给老师傅一张**派工单（契约卡）**。这张卡上写死四样东西：

1. **这步只能干嘛**（ALLOWED）
2. **这步禁止干嘛**（FORBIDDEN）
3. **这步必须交出什么活**（PRODUCES）
4. **交的活怎么才算过关**（EXIT CONDITION + 门禁）

老师傅能看到的"流程"，**永远只有这张卡**。他看不到、也改不了背后真正管流程的那套程序。

> 这就是"模型无关"的第一道闸：**模型眼里的世界，是 Runtime 裁剪好、喂给它的一张卡。**

---

## 3. 走流程：每一步都被机器卡着

### 工序和工位，是两回事

- **工序（phase）** = 流水线的第几道工序，比如"第 3 道：规则建模"
- **工位（status）** = 老师傅此刻"停在哪"，比如"正在干"、"等主管点头"、"干完了等下一道"

老师傅可能想一口气把活干完，但质检系统会在他每想推进时**拦住他检查**。7 种工位状态：

| 工位 | 大白话 |
|---|---|
| 正在干 | 活还没交，先别想下一步 |
| 干完待检 | 活交了，等机器质检 |
| 等主管确认 | 有东西要人拍板，卡住了 |
| 等老板批 Excel | 最后要不要出 Excel，等人说 |
| 已标待审自动放行 | 自动模式下，人工环节"记一笔待审、先放你过去" |
| 强制人工介入 | 同一道工序机器质检连挂 3 次，报警叫人来 |
| 全部完成 | 结束 |

**一句话：工序告诉你"干到第几步了"，工位告诉你"这一步现在卡在哪"。**

### 谁决定能不能往下走？机器，不是模型

每道工序干完，要过一道**质检关卡（门禁）**。判定方式就一条铁律：

> **机器跑出来的结果 exit=0 就是过，exit=1 就是不过。**

老师傅**不能自己宣布"我干完了"**——那不算数，得质检系统的程序点头。而且质检有三种：

| 门禁 | 谁说了算 |
|---|---|
| 机器门 | 跑一段确定性程序，看结果 |
| 人工门 | 等真人回复（但放不放行，程序只看"运行模式 + 人的意图"，不听模型自证） |
| 许可门 | 问"要不要生成 Excel"，人说了算 |

### 改砸了怎么办？有界返修

同一道工序，机器质检**连续挂 3 次**，系统就自动报警"强制人工介入"，把主管拉进来。防止老师傅"改一版不过、再改一版还不过"地无限空转。

---

## 4. 为什么老师傅「耍不了花招」？

他脑子里最想干的几件"偷懒的事"，qamaster 全都从机制上堵死了：

| 老师傅想干的事 | qamaster 怎么堵 |
|---|---|
| 跳过某道工序直接往下干 | `next` 只能走"当前+1"，跳步直接拒绝 |
| 自己宣布"干完了" | 门禁是机器判定的，模型没资格宣布 |
| 倒退回去假装重来（耍赖） | `fail` 只能回退到"更早"的工序，禁止"前进式"乱跳 |
| 改厂里的台账/经验本 | MANIFEST、KB 这些共享档案**锁在档案室**，模型只能看，不能写 |
| 糊弄说"覆盖全都做全了" | 覆盖硬门是机器算的，做没做全、数值对不对，机器一眼看穿 |
| 凭印象填"校验通过" | 校验数值必须逐字抄机器的输出行，手填视为造假 |

> 核心就一句：**凡是"要判定、要推进、要写共享档案"的地方，按键都在 Runtime 手里，模型一个都摸不到。**

---

## 5. 一条流水线，为什么能干两种完全不同的活？

qamaster 有两条流程：一条是"需求 → 测试用例"，另一条是"需求文档 → 多角色评审 → 重构文档"。两条业务八竿子打不着，但**用的是同一条流水线（同一个 Runtime 程序），一行都没改。**

秘密在于：流水线的程序里，**没有任何一行代码写死"测试用例"或"评审"这种业务细节**。它只认一个抽象的"工单模板"。

- "需求→测试用例" = 一份 16 道工序的模板
- "需求→评审文档" = 一份 8 道工序的模板

流水线拿到哪份模板，就按哪份模板的工序和质检规则去跑。

> **结论：以后想加第三条流程，不用改流水线，只要"再填一份工单模板"就行。**
> 这就是"模型无关"的终极形态——**连"跑什么业务"这件事，都跟流水线本身解耦了。**

---

## 6. 老师傅的经验本：越用越准，但不靠模型自信

qamaster 还有一个"自我进化"的本事：每次老师傅干砸了、被人纠正，系统会自动记一笔。但它很克制：

1. **自动记，但先算"草稿"** —— 记下来的是"候选经验"，先不生效。
2. **要主管点头才算数** —— 人工"背书"后，这条经验才真正算数。
3. **或者，同一类错犯满 3 次** —— 系统才认它是"真的规律"，自动生效。

这条经验要"写进老师傅的派工单"（= 提醒他别再犯），还必须同时过两关：

- **信任关**：要么主管背过书，要么同类错≥3次
- **相关关**：这条经验和这次的需求确实对得上

两关都过了，才会在派工单里加一句"**你以前在这类活上栽过，这次注意**"。

> 这套设计的精髓：**让系统"越用越准"，但准不准、该不该用，靠的是"人工背书 + 重复次数"，而不是模型自己拍胸脯说"我这次懂了"。**

---

## 7. 落地方法：如果你想自己抄这份作业

qamaster 这套思路，**不需要任何高级技术**——它那套管流程的程序，用的全是 Python 标准库。落地就五步：

### 第 1 步：把"流程"和"干活"拆成两层
- 一层是"管流程的程序"（状态机、门禁、写档案），用**普通代码**写死，不碰模型。
- 一层是"干活的模型"，只负责在给定范围内产出内容。

### 第 2 步：把流程定义成"数据"，别写成 if/else
- 把"有几道工序、每道工序允许干啥、要交什么、怎么算过关"写进一份**配置/数据**里。
- 好处：改流程 = 改数据，不碰程序。

### 第 3 步：模型和程序之间，只留一张"派工单"
- 模型每次开工前，程序生成一张卡，写死"只能干嘛、禁止干嘛、要交什么"。
- 模型看不到、也改不了背后真正的状态机。

### 第 4 步：所有"判定"都交给机器，不交给模型
- 用"跑脚本看退出码""检查文件在不在"这类**确定性判断**来当门禁。
- 铁律：**exit 0 = 过，exit 1 = 不过**。模型没有"自我宣布完成"的入口。

### 第 5 步：共享档案锁起来，模型只能读不能写
- 台账、经验库这类跨任务共享的东西，只由程序在**加锁**的情况下写。
- 模型想改？没有这个按键。

---

## 8. 最后再背一遍那句话

> **模型负责思考，Runtime 负责控制。任何模型不可绕过。**

qamaster 的厉害，不在于用了什么高深模型，而在于它把"**流程的确定性**"从"**模型的不确定性**"里，用一套朴素的代码彻底隔离了出来。

模型随便换（GPT、Claude、别的都一样），流程该怎么走、活算不算合格，**一丝都不会变**。这就是"流程与模型无关"的全部秘密。
