## 方法动态匹配（决策表 + 方法→列映射）

根据需求特征 + 第5阶段风险清单动态选择方法。禁止机械全覆盖，禁止单方法覆盖。

### 方法选择决策表（含方法→测试类型/测试维度映射）

| 需求特征 | 首选方法 | 次选方法 | →测试类型 | →测试维度 | 适用示例 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 表单/API参数/搜索条件输入校验 | 等价类 | 边界值 | 功能（合法）/异常（非法） | 输入验证 | 注册表单、查询接口参数 |
| 必填字段缺失/字段不传 | 缺省测试 | 错误推测 | 异常 | 输入验证 | 必填入参不传、选填不传、多余未知字段 |
| 字段值类型校验 | 等价类(类型维) | 错误推测 | 异常/契约 | 输入验证 | 字符串传数值字段、数组传标量、null/空串/缺失三态 |
| 长度/数量/金额/时间阈值 | 边界值 | 等价类 | 边界 | 边界验证 | 金额上限、库存临界 |
| 多条件业务规则组合 | 判定表 | 正交实验 | 功能 | 数据验证 | 优惠券叠加规则、风控规则 |
| 大量组合参数（≥3因子×多水平） | 正交实验(pairwise) | 判定表 | 功能 | 数据验证 | 多配置项组合、矩阵测试 |
| 订单/审批/生命周期 | 状态迁移 | 场景法 | 状态迁移 | 状态验证 | 订单状态机、审批流 |

| 高风险异常/历史缺陷密集区 | 错误推测法 | 边界值 | 异常（或对应风险类型：安全/并发/幂等） | 风险验证（或对应维度） | 资金、并发、幂等区 |

> **方法→列映射（强制）**：选定方法后，用例的"测试类型"与"测试维度"列按本表填写，禁止统一填"功能测试"。`scripts/verify_cases.py` 的测试类型种类统计据此判定方法多样性是否落地——种类过少（如全"功能"）即方法未落地。

### 次选方法的触发条件
* **补充相邻维度**：首选覆盖主维度后，次选补相邻维度（如边界值首选覆盖阈值四值，等价类次选补合法/非法等价类的其他代表值；**边界值"刚好满足约束"的边界内邻接（min+1/max-1）属边界值方法自身的 4 值之一，不由等价类兜底**，见下"边界值 4 值模型"）
* **首选不适用**：需求无明确阈值则边界值不适用，用次选等价类替代
* **风险扩覆盖**：P0/P1 风险区首选+次选均可使用以扩大覆盖；P2/P3 区通常首选即可

## 边界值 4 值模型（强制·防"测试通过却漏边界内 bug"）

> 经典 BVA 的边界内邻接（min+1/max-1，**刚好满足约束、应当通过**的那一档）是历史最高 bug 产出点（off-by-one：边界点写错常在"恰好等于"与"刚好满足"之间分叉）。本 skill 边界值采用 **4 值模型**，每档独立用例、不得合并、不得由等价类兜底：

| 档 | 取值 | 语义 | 预期 | 关键词契约（`config/validation_rules.json`） |
| -- | -- | -- | -- | -- |
| 最小 | min（下限点） | 边界点，刚好在边界上 | 应通过/按业务定 | `boundary_min_kw` |
| 最大 | max（上限点） | 边界点，刚好在边界上 | 应通过/按业务定 | `boundary_max_kw` |
| 临界 | 恰好=边界点 | 与 min/max 重叠，强调"恰好落在边界" | 同 min/max | `boundary_critical_kw` |
| 边界内 | min+1 / max-1 | **内邻接，刚好满足约束、应通过** | **应通过** | `boundary_inside_kw` |

* **不得用"临界"覆盖"边界内"**：临界=恰好等于边界点（与 min/max 同点），**不是** min+1/max-1；二者语义不同，用例不可互相替代。
* **不得由等价类兜底**：等价类只取"典型代表值"，不保证取 min+1/max-1 这个特定内邻接值；边界内必须由边界值方法自身覆盖。
* `scripts/verify_cases.py` 边界深度统计 4 档，缺任一档（含边界内=0）→ `⚠ 疑似边界深度不足`，供 selfcheck 检查 2/3 复核补齐。

## 多方法组合（强制·防单方法机械）

一个需求通常含多维度特征，须**组合多种方法**，禁止单方法覆盖：

* 按"需求特征×维度"分别匹配方法。示例：订单创建 = 输入校验[等价类] + 数量阈值[边界值] + 订单生命周期[状态迁移] + 支付风险[错误推测法]
* 每个需求至少评估 7 种方法是否适用，不适用的注明"不适用"（可追溯）
* 禁止全部用例只体现一种方法——`verify_cases.py` 测试类型种类 <3 时提示方法单一，须补齐

> 多方法组合是"覆盖完整"的前提；单方法只覆盖一个维度，必然漏测。真实产物"全功能测试"即为单方法未组合的反例。

## 风险驱动的方法深度（对照第5阶段风险清单）

方法深度按风险等级分层（与"组合爆炸控制"一致，扩展到所有方法）：

| 风险等级 | 方法深度 | 具体要求 |
| -- | -- | -- |
| P0（资金/支付/权限/状态流转/数据一致性/安全） | 全量穷举 | 边界值：min/max/临界/边界内(min+1/max-1)/负数/超限全覆盖；状态迁移：合法流转+非法流转拦截+回滚+终态全覆盖；等价类：合法+非法等价类全量；错误推测：穷举 0.6 隐含风险相关方向 |
| P1（并发/幂等/缓存一致性/MQ一致性/接口契约） | 全量或pairwise | 同 P0，但多因子可用 pairwise；并发/幂等须专项用例 |
| P2（普通业务流程/常规边界） | 采样覆盖 | 边界值取 min/max/边界内(min+1/max-1) 代表值（临界与 min/max 重叠，按需）；状态迁移覆盖主流转+关键非法流转；等价类取典型合法+非法 |
| P3（低频/边缘场景） | 最小采样 | 仅代表性典型值，不追求穷举 |

> **P0 风险强制对应方法（动态匹配的核心）**：每个 P0 风险项须有对应方法用例——资金→边界值全量+错误推测；状态流转→状态迁移（含非法流转+回滚+终态）；权限→错误推测（越权）+权限验证；并发→错误推测（竞态）+并发专项；幂等→幂等专项；数据一致性→数据验证+错误推测。P0 风险无对应方法用例 → selfcheck 检查8 阻断（见 `references/selfcheck.md`）。

## 组合爆炸控制（pairwise 优先）

> **AND 门真值表 ≠ 因子×水平组合（强制区分·防误收敛）**：本节"组合爆炸控制"针对**因子×水平**（多因子各多取值，笛卡尔积爆炸，用 pairwise 收敛）；**不针对 AND 门前置条件**（每条件仅布尔二值，2ⁿ 行有界）。AND 门须按上"各方法适用说明·判定表"条目穷举 2ⁿ 全行，**不得以本节 pairwise/采样为由缩减 2ⁿ 行数**。"全量覆盖"在 AND 门语境=2ⁿ 真值表全行，在因子×水平语境=pairwise 两两覆盖，二者不可混淆。

判定表与正交场景下用例易爆炸，与"拒绝过度设计"冲突。采用分层收敛策略：

* **高风险组合：全量覆盖。** 涉及 P0/P1 风险（资金、权限、状态流转、并发、幂等）的因子组合必须全量。
* **中风险组合：pairwise 两两覆盖。** 用两两组合保证每对因子的水平组合至少出现一次，替代全排列。
* **低风险组合：采样覆盖。** 仅取代表性典型值，不追求穷举。
* **无关因子：剔除。** 对结果无影响的因子不进入组合。

### pairwise 操作性
* 两两组合可由工具生成（如 AllPairs、正交表），或人工选取覆盖每对因子水平组合的代表性用例
* LLM 生成时：列出全部因子×水平，按"每对至少出现一次"原则选取最小用例集，禁止全排列

禁止：以"覆盖全面"为由对低风险因子做全排列，制造大量重复低价值用例。

## 错误推测法（基于经验/历史缺陷）

错误推测法基于经验与历史缺陷模型，须对照以下推测方向穷举（引用 `references/quality_rules.md` 0.6 隐含风险）：

* **资金/数值类**：负数金额、超限金额、精度丢失、资金反向操作、并发扣减超卖
* **并发/幂等类**：重复提交、重复消费、重复发货/提现、竞态条件、乐观锁冲突
* **状态类**：非法状态流转、终态后操作、状态回滚异常、状态机绕过
* **权限类**：水平越权、垂直越权、Token 伪造/重放、权限绕过、会话固定
* **缓存/MQ 类**：缓存不一致、缓存失效未更新、MQ 消息丢失/重复/乱序、最终一致性异常
* **时间边界类**：跨天/跨月/跨年、闰年、Token 失效临界、有效期边界
* **异常处理类**：超时、重试风暴、补偿失败、回滚不全、降级异常
* **注入/安全类**：SQL 注入、XSS、CSRF、SSRF、路径遍历、敏感信息泄露
* **接口契约类**：必填字段不传、选填字段不传、多余未知字段、类型错传（字符串传数值字段、数组传标量）、null/空串/缺失三态混传

> 错误推测法的测试类型填"异常"或对应风险类型（安全/并发/幂等），测试维度填"风险验证"或对应维度。P0/P1 风险区须全量覆盖上述相关方向。

## 各方法适用说明

* **等价类**：表单、API参数、搜索条件。合法+非法等价类。
* **边界值**：长度、数量、金额、时间。4 值：min/max/临界/边界内(min+1/max-1)（见"边界值 4 值模型"，边界内不得省略、不得由等价类兜底）。
* **判定表**：多条件业务规则。**AND 门前置条件须穷举 2ⁿ 真值表全行**：当规则为"N 个前置条件须同时/全部满足"（每条件布尔：成立/不成立）时，须枚举 2ⁿ 全行——全符合(11..1)、全不符合(00..0)、各"部分符合"（恰一/恰二…条件成立）、各"单条件不成立"+边界；**不得以"每条件效应各测一次"的短路覆盖（MCDC 式）替代**。2ⁿ 行数有界（3 条件=8 行、4 条件=16 行），**不属"组合爆炸"，不适用 pairwise 收敛**。
* **正交实验**：大量组合规则（pairwise 优先）。
* **状态迁移**：订单、审批流、生命周期。合法流转+非法流转拦截+回滚+终态。
* **场景法**：端到端流程。
* **错误推测法**：高风险异常场景（见上"错误推测法"清单，对照 0.6 隐含风险）。

### 三类收敛规则（防爆炸·强制）

1. **scope 受控**：三类只对"变更接口 + 变更字段 + 受影响规则/场景"做，不外溢到未变更部分。G 类只对"变更影响清单"的受影响规则 `R<序号>`、H 类只对受影响场景 `SC<序号>` 做，不重测全量规则/场景。
2. **深度分级**：直接套本文件"风险驱动的方法深度"表（P0 全量 / P1 全量或 pairwise / P2-P3 采样），不另造分级。
3. **去重保护**：不同类别（契约 A-F vs 规则 G vs 场景 H）即便断言相似也**不合并**（测试意图/维度/类型不同）；仅"类别+测试点+字段+断言+维度+类型"全同才合并（见 `references/dedup_coverage.md` 去重原则）。

### 跳过判定

* 变更接口无受影响规则 -> 跳 G 类；无受影响场景 -> 跳 H 类。
* 纯参数契约变更（如仅类型变更）可能只走 A-F。
* 同一字段在契约类（测 syntax：接/拒都对）与规则类（测 semantics：业务规则成立）各测各的，互不替代--契约类全绿不等于安全（如"券+积分叠加算错"属 G3、"券重复核销"属 G2）。

> 矩阵三类覆盖由 `scripts/verify_cases.py` #6 反向接口追溯校验（见 `references/dedup_coverage.md` #6、`references/selfcheck.md` 检查16）。
