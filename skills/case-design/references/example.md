## 待确认问题与假设清单（示例）

> 统一展示：待确认问题（Q，阻断）与假设（A，非阻断）同列一张清单向用户展示，假设不再仅沉于交付报告（闭合"假设未在问题列表展示"）。问题与假设共用 ID 空间。

| 问题/假设ID | 类型 | 问题描述 | 影响范围 | 风险等级 | 状态 | 建议回答角色 |
| ---- | -- | ---- | ---- | ---- | ---- | ---- |
| Q1 | 业务规则 | 是否允许重复提交订单（幂等） | 订单创建 | P1 | 待确认(阻断) | @开发 |
| Q2 | 数据规则 | 库存扣减时机：下单即扣 vs 支付后扣 | 库存、订单 | P0 | 待确认(阻断) | @开发 |
| Q3 | 异常规则 | 库存不足时是拒绝下单还是允许超卖 | 订单 | P0 | 待确认(阻断) | @产品 |
| A1 | 状态机 | 待支付后续状态（已支付/已发货/已收货）及逆向流转，需求文档未明确 | 订单 | P2 | 假设(非阻断,事后确认) | @开发 |

> 存在 P0 未确认 → 停止，等待用户回复。A1 为连跑/轻量模式下登记的假设（状态机需求未明确，须回显本清单，受影响用例关联规则标 `假设A1`），提示用户事后定向确认；完整模式下状态机属 P1 须阻断提问，不得静默假设。

## 范例2：状态迁移（订单状态机）

> 锚定与"订单创建"不同的设计方法：状态迁移法。展示合法流转、非法流转、回滚的用例结构。**需求文档仅明确"待支付"状态，后续状态机未定义**--完整模式下须作为问题提问（P1 阻断）；本范例为演示用例结构，连跑/轻量模式下登记为**假设 A1**（待 @开发 确认，已回显进待确认问题与假设清单），假设状态机为 待支付 → 已支付 → 已发货 → 已收货，可逆向 待支付 → 已取消、已支付 → 已退款。受影响用例关联规则标 `假设A1`。

### 状态机（澄清后确认）
```text
待支付 →[支付成功]→ 已支付 →[发货]→ 已发货 →[确认收货]→ 已收货
待支付 →[取消]→ 已取消
已支付 →[退款]→ 已退款
已发货 →[退款退货]→ 已退款（P2 假设A1，待@业务确认）
非法：已收货 → 已支付（不可逆）、已取消 → 任意状态（终态）
```

### 规则建模（示例·编号 + 来源标注）

- **R1 订单状态机** [来源:假设A1]（待支付→已支付→已发货→已收货 及逆向流转，需求未明确，登记假设待@开发确认）
- **R2 非法流转拦截** [来源:假设A1]（终态后操作/不可逆流转拦截）

> 每条规则项标注来源（需求文档/台账Q/假设A），破 rule_coverage 自证洗白（见 `references/modeling.md` 规则建模 section 来源标注、`scripts/verify_cases.py` 检查15 规则来源）。
