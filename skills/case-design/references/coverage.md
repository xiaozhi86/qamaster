# 8、测试覆盖矩阵（统一场景覆盖）

> 本章为场景覆盖的统一来源。测试需求分析维度（15.2）与测试点提取维度（15.3）在其各自阶段引用本矩阵，不再重复枚举。

## 8.1 正常场景覆盖
主流程 / 高频流程 / 标准流程 / 多角色流程

## 8.2 异常场景覆盖
输入异常 / 数据异常 / 状态异常 / 权限异常 / 服务异常 / 网络异常 / 缓存异常 / MQ异常

## 8.3 组合场景覆盖
多个规则同时成立。例如：优惠券+积分、并发+状态迁移、审批+转派。

## 8.4 跨需求场景覆盖
分析当前需求对以下的影响及反向影响：订单、支付、库存、营销、会员、消息中心、数据报表。

## 8.5 状态组合场景覆盖
状态A × 状态B；状态B × 状态C；状态C × 状态D。

## 8.6 时间组合场景覆盖
跨天 / 跨月 / 跨年 / 闰年 / Token失效临界点

## 8.7 权限组合场景覆盖
角色 × 数据归属；角色 × 状态；角色 × 操作。

## 8.8 上下游联动覆盖
上游失败 / 下游失败 / 补偿执行 / 重试执行 / 最终一致性

## 8.9 安全场景覆盖
见 `references/safety_perf.md` 安全测试维度。

## 输出要求

建立测试覆盖矩阵：

| 需求 | 规则 | 场景类型 | 覆盖状态 |
| -- | -- | ---- | ---- |
| <需求条目> | <规则> | 正常/异常/组合/跨需求/状态组合/时间组合/权限组合/上下游/安全 | 已覆盖/未覆盖 |

确保不存在高风险遗漏。

> **反向需求追溯（#4）**：覆盖矩阵须按需求条目逐条标注覆盖状态，未被任何用例覆盖的需求条目标"未覆盖"，第10阶段补齐（见 `references/dedup_coverage.md` 反向需求追溯）。
> **反向行为来源追溯（#5）**：用例 Given/When/Then 断言的业务行为须有来源三选一（需求文档/R·TP 引用/假设标记），三者皆无即疑似脑补，须转问题/假设（见 `references/dedup_coverage.md` 反向行为来源追溯、selfcheck.md 检查15）。#4 管"需求被覆盖"，#5 管"断言有来源"，互补闭环。
