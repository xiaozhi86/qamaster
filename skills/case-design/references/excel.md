# 21.1 输出原则

仅当用户明确要求"生成Excel / 导出Excel / 输出xlsx"时执行。否则仅输出Markdown。

# 21.2 Excel格式要求

必须满足：UTF-8兼容、自动列宽、自动换行、一行一个测试用例、禁止合并单元格、表头冻结、支持筛选。

# 21.3 Markdown与Excel保持一致

字段必须完全一致：列数相同（15列）、字段顺序相同（见 `references/modeling.md` 字段顺序表）、取值相同（含 20.7-20.10 四个固定值列）、内容相同。禁止字段不一致或内容不一致。

# 21.6 Excel-only 快捷路径（强制）

## 触发条件
同时满足：
* 用户仅要求生成 Excel 测试用例
* 已存在已生成的 .md 测试用例文件

## 执行流程
```
跳过完整设计流程（主执行流程）
↓
源 .md 一致性校验
↓
校验通过 → 按 21.4 字段规范直接生成 Excel
校验不通过 → 拒绝转换，提示用户修正
↓
保持 Markdown 与 Excel 字段、内容完全一致
```

## 源 .md 一致性校验（强制）
转换前必须校验源 .md 是否符合 21.4 字段规范（默认单文件 `case-design-out/TestCases_<需求标识>.md`；拆 PART 时对每个 `case-design-out/TestCases_<需求标识>_PARTn.md` 逐文件校验，全部通过后合并转换）。校验项：
* 包含全部 15 个字段列
* 字段顺序与 21.4 一致
* 测试类型 / 用例等级 / 测试维度取值在允许枚举内
* 用例名称符合 20.5 规范（【模块】【功能】【场景】【预期】四段齐全）
* Then 断言可观测（非模糊表达）
* 无杜撰存储信息（符合 `references/quality_rules.md` ch12）
* 用例ID 唯一不跳号

### 校验结果必须向用户输出（防自证）
禁止 agent 单方面声明"校验通过"即推进转换。必须向用户输出**转换前核对报告**，让用户可复核：

| 校验项 | 核对结果 | 依据 |
| -- | ---- | ---- |
| 字段列数 | 通过/不通过 | 实际列数=15（或 X，缺失 Y） |
| 字段顺序 | 通过/不通过 | 与 21.4 顺序对比 |
| 枚举合规 | 通过/不通过 | 测试类型/等级/维度违规条数=Z |
| 用例名称规范 | 通过/不通过 | 不符合 20.5 四段格式的条数=Z |
| 断言可观测 | 通过/不通过 | 模糊断言条数=Z |
| 存储合规 | 通过/不通过 | 杜撰存储条数=Z（见 ch12） |
| ID 连续 | 通过/不通过 | 跳号/重复 ID 列表 |

要求：
* 每项必须填实际核对数值，禁止只填"通过"
* 报告须随校验一并输出给用户，禁止只给结论不给依据
* agent 不得以"已校验"为由拒绝出示报告

### 校验不通过处理
若任一项不通过：禁止直接转换。输出【源文件不符合转换规范清单】：

| 编号 | 不合规项 | 问题描述 |
| -- | ---- | ---- |
| 1 | 字段缺失/取值越界/断言模糊/杜撰存储/ID跳号 | <问题描述> |

并提示用户：
* 选项A：按完整设计流程重新生成 .md（走人工审核门禁）
* 选项B：人工修正源 .md 后重新转换

禁止跳过校验强行转换导致字段错位。

## 强制
* 必须以现有 .md 为唯一数据源
* 必须逐条映射，1 条 .md 用例 = 1 行 Excel
* 字段顺序、取值必须与 21.4 及 .md 完全一致
* 生成后须与 .md 做字段一致性核对
* 必须保留用户原始 .md 文件名（位于 `case-design-out/` 下），禁止重命名、覆盖或改写源 .md 文件
* Excel 文件名默认与源 .md 同名（仅扩展名由 .md 替换为 .xlsx，输出到 `case-design-out/` 下），如用户指定其它名称则从其指定

## 禁止
* 已有 .md 仍重走完整设计流程
* 在 Excel-only 场景下重复生成或重新设计 .md
* 自行增删改测试用例内容
* 跳过字段一致性校验

## .md 不存在时的处理
若用户仅要求 Excel，但 .md 测试用例文件不存在（`case-design-out/` 下无 `TestCases_<需求标识>.md`）：必须先按完整设计流程生成 .md（并走人工审核门禁），再进入 Excel 生成。禁止在缺失 .md 的情况下凭空直接生成 Excel。

# 21.7 Excel 生成机制（工具层·强制）

> 本节解决"用户已要求生成 Excel，但 .xlsx 文件未实际产出"的问题。根因：.xlsx 是二进制 ZIP 归档（非纯文本），无法用文本写入工具直接生成合法文件；本节镜像 `references/output_write.md` 对 .md 的工具层约束，补齐 Excel 的生成机制。

## 核心约束：必须经脚本执行产出，禁止文本写入 .xlsx
* **必须**：写一段 Python 脚本（使用 openpyxl）并经 Bash 执行，由脚本读取源 .md、解析用例表、按 21.4 字段规范写出 .xlsx（源 .md 与输出 .xlsx 均位于 `case-design-out/` 下；临时生成/校验脚本亦置于 `case-design-out/` 下用完即删），脚本运行成功后 .xlsx 才算生成
* **禁止**：用文本写入工具（Write/Edit 等）直接把内容写进 `.xlsx` 文件——产出的是损坏文件，等同未生成
* **禁止**：仅在对话中粘贴 Markdown/CSV 表格冒充"已生成 Excel"
* **禁止**：口头声明"已生成 Excel"而磁盘上无对应 .xlsx 文件
* **禁止**：因任何环节失败（依赖缺失、解析失败、脚本异常）而静默放弃——失败必须按"生成失败处理"向用户显式报错

## 脚本职责（一次性完成）
脚本须在一次执行内完成全部工作，禁止"先建空表头再逐行追加"式分次写入：
* 读取源 .md 测试用例文件，逐行解析用例表（表头 + N 条用例）
* **只读取 15 列用例表**：`.md` 中的"规则建模/风险清单/测试点清单"等追溯性 section（见 `references/output_write.md` 追溯性 section）**不读取、不校验、不输出到 Excel**；脚本以"用例ID"表头行定位用例表起始，section 在表前不影响解析
* 按 21.4 的 15 个字段顺序写出表头行
* 逐条映射：1 条 .md 用例 = 1 行 Excel，字段顺序、取值与 .md 完全一致
* 套用 21.2 格式：UTF-8 兼容、自动列宽、自动换行、一行一用例、禁止合并单元格、表头冻结、支持筛选
* 固定列填 21.4 规定的固定值（编辑模式=STEP、标签=AI、责任人=AI、用例状态=Completed，见 20.7-20.10）
* 文件名：默认与源 .md 同名（扩展名 .md→.xlsx，输出到 `case-design-out/` 下），用户指定则从其指定；禁止重命名/覆盖源 .md
* **多文件源（仅 PART 溢出拆分时）**：默认源为单文件 `case-design-out/TestCases_<需求标识>.md`，直接生成 `case-design-out/TestCases_<需求标识>.xlsx`。仅当源为多个 `case-design-out/TestCases_<需求标识>_PARTn.md`（合并体压缩后仍超预算才拆）时，**聚合为单一 .xlsx**——Excel 由 openpyxl 脚本经 Bash 产出（非模型直接写 content），不受 32k 输出上限约束，故 PART 合并无障碍。脚本读取全部 PART 的 15 列用例表，合并入单一 sheet、按用例ID排序（用例ID 跨文件全局唯一连续不跳号，合并后仍连续），行数校验 N=各 PART 用例数之和，逐单元格一致性逐行比对各自源 .md。如用户要求按 PART 分文件，则一 .md 对应一 .xlsx 逐文件生成与校验。
* 脚本退出码非 0 即视为生成失败

## 生成后强制验证（防"假生成"）
脚本执行成功后，**立即**对产出文件做只读验证，全部通过方可进入数据完整性校验：
* **落盘校验**：.xlsx 文件存在于磁盘且非空（文件大小 > 0）
* **可读校验**：能用 openpyxl 正常打开（非损坏文件）
* **行数校验**：数据行数 = 源 .md 用例条数 N（不含表头）；PART 合并时 N = 各源 .md 用例条数之和
* **列数校验**：列数 = 15，表头与 21.4 顺序一致
* 验证任一不通过 → 判定生成失败，按"生成失败处理"报错，**不得**在交付摘要中声明已生成

## 生成后数据完整性校验（内容级·强制·自动执行）
> 上文"生成后强制验证"只保证文件**结构**正确。本节进一步对 Excel 内的测试用例**数据**做内容级完整性校验，防止"行数对、内容错"。结构验证通过后**必须自动执行**本节，全过才算生成成功。

校验项（逐行、逐单元格执行）：
1. **逐单元格一致性**：Excel 每行每列单元格内容 == 源 .md 对应单元格（去首尾空白后比对），任一不符记为"内容不一致"（重点防：字段错位、内容丢失、截断）
2. **必填字段非空**：每行的 用例ID / 关联需求ID / 关联规则 / 测试类型 / 所属模块 / 测试维度 / 用例名称 / Given / When / Then 共 10 个业务字段均非空
3. **固定列取值正确**：编辑模式=STEP、标签=AI、责任人=AI、用例状态=Completed（见 20.7-20.10）
4. **用例等级合规**：用例等级列取 P0-P3、与源 .md 一致（见 20.6）
5. **ID 唯一不跳号**：用例ID 全局唯一、与源 .md 序列一致不跳号
6. **枚举合规**：测试类型 / 测试维度 取值在允许枚举内（与源 .md 一致，复用 21.6 口径）
7. **用例名称规范**：用例名称列符合 20.5 四段格式【模块】【功能】【场景】【预期】（与源 .md 一致）
8. **断言可观测**：Then 列非模糊表达（复用 `references/selfcheck.md` 检查4口径；记录模糊断言条数）
9. **存储合规**：Then 列无杜撰表名/字段名/Redis Key/Topic/Index/Bucket（复用 `references/quality_rules.md` ch12/检查9口径）

校验结果必须向用户输出【Excel 数据完整性核对报告】（防自证，类似 21.6 转换前核对报告）：

| 校验项 | 核对结果 | 依据 |
| -- | ---- | ---- |
| 逐单元格一致 | 通过/不通过 | 不一致单元格数=Z（列出位置） |
| 必填非空 | 通过/不通过 | 空必填单元格数=Z（列出位置） |
| 固定列取值 | 通过/不通过 | 违规单元格数=Z |
| 用例等级合规 | 通过/不通过 | 等级非P0-P3或与源.md不符条数=Z |
| ID 唯一不跳号 | 通过/不通过 | 重复/跳号 ID 列表 |
| 枚举合规 | 通过/不通过 | 越界条数=Z |
| 用例名称规范 | 通过/不通过 | 不符合 20.5 四段格式条数=Z |
| 断言可观测 | 通过/不通过 | 模糊断言条数=Z |
| 存储合规 | 通过/不通过 | 杜撰存储条数=Z |

要求：
* 每项必须填实际核对数值，禁止只填"通过"
* 报告须随校验一并输出给用户，禁止只给结论不给依据
* agent 不得以"已校验"为由拒绝出示报告

### 校验不通过处理
任一项不通过 → 判定 Excel 数据不完整，**不算生成成功**，按问题类型分流修正：
* **结构类问题**（逐单元格不一致 / 必填空 / 固定列错值 / ID 跳号 / 枚举越界）→ 多为脚本映射或源 .md 问题：在内存内修正脚本逻辑或核对源 .md 后**重新整体生成 .xlsx 并重跑全部校验**，禁止用 Edit 补打 Excel 单元格
* **内容质量类问题**（断言模糊 / 杜撰存储）→ 问题源于源 .md 本身：回到源 .md 按 `references/output_write.md` "修改执行流程·起点判定"修正（确定重走起点后从该阶段依次顺序执行至第14阶段），.md 重新走完整输出后再重新生成 .xlsx 并重跑校验
* **禁止只改 Excel 不改 .md**：导致 .md 与 .xlsx 不一致，违反 21.3；任何修正必须以 .md 为唯一数据源，Excel 由脚本重新产出
* 修正后必须**重新跑完整两段校验**（结构验证 + 数据完整性校验），不得只重跑失败项

## 依赖兜底
* 检测到 openpyxl 不可用 → 尝试 `pip install openpyxl`（或用户环境等价安装命令）后重试一次
* 安装失败或仍不可用 → 停止生成，向用户显式报错："Excel 生成依赖 openpyxl，当前环境缺失且自动安装失败，请手动安装后重试"，**不得**静默放弃或降级为文本输出

## 生成失败处理
生成失败时输出【Excel 生成失败报告】：

| 失败环节 | 现象 | 处理建议 |
| -- | ---- | ---- |
| 依赖缺失 | openpyxl 未装且安装失败 | 手动安装 openpyxl 后重试 |
| 解析失败 | 源 .md 用例表无法解析 | 检查 .md 格式 / 走 21.6 一致性校验 |
| 脚本异常 | 脚本运行报错退出码非 0 | 附报错信息，修正后重跑 |
| 结构验证不通过 | 文件损坏/行数不符/列数不符 | 重新生成，禁止交付半成品 |
| 数据完整性不通过 | 内容不一致/必填空/固定列错值/ID跳号/枚举越界/断言模糊/杜撰存储 | 按本节"校验不通过处理"修正后重跑两段校验 |

等待用户处理，**禁止**在失败状态下声明 Excel 已交付。

## 与第19章写入约束的关系（豁免说明）
* `references/output_write.md` "单文件写文件调用 ≤ 2 次（多文件按文件计）、禁 Edit/仅 Write"是针对 **.md 文本落盘**的约束
* Excel 生成走"写脚本 + Bash 执行 + 读结果验证"路径，**不**计入 .md 的写入次数，**不**受"仅 Write"约束
* 但 Excel 仍遵守其自身的"脚本一次产出 + 生成后验证"约束，不得分次追加写入同一 .xlsx
* Excel 数据校验不通过时，修正方式是**重新整体生成 .xlsx**（内存内修正脚本/源 .md 后重跑），**禁止**用 Edit/单元格编辑直接改已落盘的 .xlsx（与"禁 Edit"一致，避免 .md 与 .xlsx 不一致）

## 强制（汇总）
* 必须经 openpyxl 脚本执行产出 .xlsx，禁止文本写入 .xlsx
* 脚本须一次完成读取+解析+写出+格式化，禁止分次追加
* 生成后必须落盘/可读/行数/列数四项结构验证全过
* 结构验证通过后必须自动执行数据完整性校验九项，全过才算生成成功
* 数据完整性校验结果必须向用户输出【Excel 数据完整性核对报告】，禁止只给结论不给依据
* 依赖缺失须尝试安装并兜底报错，禁止静默放弃
* 失败须显式报错，禁止声明已交付
* 校验不通过必须以 .md 为唯一数据源修正后重新整体生成并重跑两段校验，禁止直接改 .xlsx 单元格
* 交付摘要声明 .xlsx 前，必须确认文件在磁盘上真实存在并通过结构+数据两段验证（见 SKILL.md 25 交付闸）
* Excel 生成/校验用的临时脚本（`.py`）、中间文件（CSV/JSON/txt）置于 `case-design-out/` 下，在 .xlsx 通过两段校验后立即删除（见 `references/output_write.md` ch30），禁止残留

## 禁止（汇总）
* 用 Write/Edit 直接写 .xlsx
* 只在对话粘贴表格冒充 Excel 生成
* 口头声明已生成而磁盘无文件
* 静默降级（生成失败不报错）
* 分多次脚本调用追加写同一 .xlsx（建表头→补行）
* 跳过生成后结构验证即声明完成
* 结构验证通过但跳过数据完整性校验即声明完成
* 用 Edit/单元格编辑直接改已落盘 .xlsx 修正数据（须改 .md 后重新整体生成）
* 数据完整性校验只重跑失败项不重跑完整两段校验
