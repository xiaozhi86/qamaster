# 一分钟上手

> 给最终用户的极简卡片。三步即可用。详细说明见 `README.md`。
>
> 版本：v0.11.10 · 更新：2026-08-18

---

## 第 1 步 · 触发

在 Claude Code 里输入：

```
/case-design
```

---

## 第 2 步 · 提供需求

把下面模板填好发给它（需求文档粘贴到两个 `<<<>>>` 之间）：

```
【需求标识】
订单创建-20260702

【业务需求描述】
<<<需求文档开始>>>
（在这里粘贴你的需求文档）
<<<需求文档结束>>>
```

它会先问你几个澄清问题（如库存何时扣减、是否允许重复提交）——**逐条回答**即可，可批量回（如"Q1 按方案A，Q2 按方案B"）。

> 各阶段出口有机器校验 + 对抗式 critique，质量内置；你只需回答澄清问题与最后审核。

> 想省事、批量跑：开头加一行 `连跑模式`；低风险小改：加 `轻量模式`。

> 有开发/架构设计文档？加一段 `【设计文档】<<<设计文档开始>>>...<<<设计文档结束>>>`，其"测试要点"章节会被强制逐条覆盖（漏一条不通过）。更多可选输入（技术实现摘要/业务规则/历史缺陷）见 `README.md` §6.3。

---

## 第 3 步 · 审核回复

它生成用例后会停下等你审核。二选一：

- **没问题** → 回复 `审核通过`
  → 自动生成知识总结，并问你要不要 Excel；要就回 `要`。
- **有问题** → 直接说改哪里，如 `TestCases_xxx 断言改为返回400` → 它改完再请你审核。

---

## 产出（自动生成在项目根目录下的 case-design-out/ 子目录）

`case-design-out/TestCases_<需求标识>.md`（用例）· `case-design-out/TestCases_<需求标识>.xlsx`（要 Excel 才有）· `case-design-out/Knowledge_<需求标识>.md`（知识总结）· `case-design-out/REQ_<需求标识>.md`（需求文档，自动落盘，别删）· `case-design-out/Clarification_Ledger_<需求标识>.md`（澄清台账，别删）· `case-design-out/MANIFEST.md`（需求索引）

> 另有三份**跨需求共享知识库**由 Runtime 自动维护（`KB_lessons.md` 经验库 / `KB_business.md` 业务知识库 / `KB_expert.md` 专家方法论库），沉淀你历次纠正并跨需求复用，无需手动编辑。

> 所有产出物统一写入项目根目录下的 `case-design-out/`，目录不存在会自动创建。
> 生 Excel 需先装 openpyxl：`pip install openpyxl`
